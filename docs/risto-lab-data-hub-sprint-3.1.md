# Sprint 3.1 — Local Data Hub (pilot)

Implemented: same-origin IndexedDB recipe archive with immutable revisions, atomic compare-and-swap, idempotent writes and history reads; BroadcastChannel metadata-only notifications; explicit save/load in Recipe Manager and explicit read/import in Matrix. Ingredient IDs minted when creating or migrating rows, persisted through native JSON, validated for uniqueness. New Recipe Manager recipe IDs are UUID-based; legacy IDs retained. Recipe adapter includes ingredient IDs in source snapshots where available. Pilot namespace `hub-local` is reserved for Data Hub imports. Imported compositions are pinned and remain draft-only; automatic dependency invalidation/rebinding and supplier integration are not implemented. Existing file backups remain supported. No autosave or automatic overwrite, no authentication, no server, no cross-device data, no production deployment. Data stored in same browser origin; shared device users can access it; do not use confidential real data in pilot. Deleting browser site data deletes local history. Tests cover two tabs, persistence after reload, stale writes, stable ingredient IDs and explicit import. Full backup/history restore UI and shared ingredient identities in Supplier Manager are subsequent tasks.
