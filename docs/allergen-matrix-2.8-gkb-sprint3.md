# 2.8 GKB Sprint 3 — Recipe Manager Integration

Native `ristolab.recipe-archive/1` version 1.0.0 is read directly; select one recipe and an explicit archive namespace. Only the selected root and its recursive dependencies are imported. Recipe IDs are namespaced (`rm:<scope>:<id>`); original IDs, declared/proposed/unknown provenance, source and canonical snapshot are preserved. No inference from name, no automatic match to existing Matrix dishes. The user explicitly links the imported revision to an ingredient. Imported compositions are read-only in the manual editor; update by reimporting using the same scope. Identical reimports are idempotent; changes in a child propagate to a new parent revision, existing links remain pinned and flagged. Invalid, missing, cyclic and incomplete selected graphs are rejected transactionally. No automatic allergy confirmation or absence; old lexical clues retained. Local JSON, no live sync; original Recipe Manager ingredient rows do not have persistent IDs, so stable cross-app ingredient IDs and Supplier Manager remain later work. IDs outside the adapter's safe length/character contract are rejected visibly rather than rewritten. No production deployment until QA.
